# ShikshaSetu AI Model Training — Milestone 1

## Model objective
A Weka Random Forest estimates the likelihood of a narrowly defined future outcome:

- `1`: the next reporting-period subject-average mark falls by at least 10 percentage points compared with the current-period subject-average mark.
- `0`: it does not.

This is a future academic-deterioration estimate, not a diagnosis, causal explanation, permanent label, or automatic decision. The UI's LOW/MEDIUM/HIGH band is provisional.

## Dataset
Use `training-template.csv` as the exact header. One row is one student at one reporting-period snapshot. Predictors must be known at or before that snapshot; the target is calculated only after the later, non-overlapping reporting period is complete.

| Field | Meaning |
|---|---|
| `student_key` | Random stable pseudonymous key; used only to keep each student's rows together in the split. Never put names, email, roll numbers or real IDs here. |
| `attendance_percent` | Attendance known at snapshot date, 0–100. |
| `internal_marks_percent` | Internal marks known at snapshot date, 0–100. |
| `assignment_completion_percent` | Assignment completion, 0–100. |
| `previous_failures` | Prior course/subject failures known at snapshot date. |
| `absence_count` | Absences in the defined reporting window. |
| `consecutive_absences` | Maximum recorded consecutive absence streak. |
| `recent_mark_drop` | Largest prior-to-latest subject mark decline in percentage points. |
| `repeated_low_results` | Number of subjects with two consecutive results below 40%. |
| `next_period_deterioration` | Observed future target, exactly 0 or 1. |

### Data safeguards
- Never leak future marks into predictor columns.
- Do not create labels from the old rule-based risk score; that would only imitate the heuristic.
- Keep all rows from the same student in one partition; this trainer performs a grouped 80/20 split using `student_key`.
- Exclude names, email, student ID, age, sex, caste, religion, disability, address, audit group, mood, counselling notes and other sensitive/protected attributes.
- Wellbeing data must remain voluntary and separate from academic prediction.
- Minimum software guard: 100 labelled rows, 30 distinct students, and at least five examples of each class in both partitions. This is not a statistically sufficient sample-size claim. Use much larger, multi-cohort data where possible.
- De-identify and obtain institution approval before training. Current backend authentication/authorization is not production-ready.

## Run and train
From the backend folder:

```powershell
mvn clean package
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

Status:
```powershell
Invoke-RestMethod http://localhost:8080/api/ai/model/status
```

Train (CSV file must be populated with approved labelled longitudinal data):
```powershell
$form = @{ file = Get-Item ".\ai-training\your-anonymized-labelled-data.csv" }
Invoke-RestMethod -Uri "http://localhost:8080/api/ai/model/train" -Method POST -Form $form
```

Assess a student already in the database:
```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/ai/students/1/assessment" -Method POST
```

Model artifact: `./data/ai-models/student-deterioration.model`; override with environment variable `AI_MODEL_PATH`.

## Evaluation
Training response includes accuracy, precision, recall, F1, ROC AUC, TP/TN/FP/FN, row counts and distinct-student counts. The reported test split is grouped by student, but is still only an initial random holdout. Before any live use, add time-separated later-term validation, calibration, subgroup error analysis, drift monitoring and independent review.

## Mentor Support Loop mapping
1. **Identify early:** model probability plus current academic and dated trend features.
2. **Understand:** observed feature snapshot, threshold signals and data-quality warnings. These are not SHAP values and do not establish causes.
3. **Recommend:** support options with a suggested action and weekly target.
4. **Connect:** mentor discusses options with the student; existing mentor feedback workflow remains intact.
5. **Track:** AI assessment snapshots are persisted in `ai_assessments`; existing risk history and feedback/follow-up features remain intact.

## Explicit limitations
- This is a real trainable pipeline, but **not trained yet**. It needs approved, labelled longitudinal data.
- Raw Random Forest probabilities are not calibrated in this milestone. Bands use provisional 0.35 / 0.65 cut-offs, not validated institutional thresholds.
- Recommendations are rule-based templates, not generated by a conversational language model.
- Human review is mandatory. The model must not autonomously assign interventions, punish, exclude, rank or permanently label students.
- A live safety escalation must connect to a staffed, institution-approved human responder service. This package does not claim that such a responder is connected.


## Model scope clarification
This release is a supervised tabular academic-deterioration classifier, not a chatbot, mental-health detector, dropout model or general-purpose student-risk model. `deteriorationProbability` estimates the labelled outcome in the target definition above. It must not be renamed or interpreted as an all-purpose probability of a student being “at risk”.

See `../../AI-MODEL-RESEARCH.md` for the model selection rationale, validation plan, fairness and privacy design, diagram mapping, and production blockers.

The frontend AI Admin Console now exposes `/api/ai/model/status` and `/api/ai/model/train`, and the Support Loop calls `/api/ai/students/{id}/assessment` only after the model status is `TRAINED_PROTOTYPE`. Until then, the original baseline assessment endpoint remains active. A model trained on approved data is still only a research prototype until later-term/external validation, calibration, subgroup auditing and governance approval are completed.
